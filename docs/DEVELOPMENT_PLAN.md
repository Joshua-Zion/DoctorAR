# DoctorAR 开发计划

## 1. 项目定位

DoctorAR 是一个在浏览器中运行的本地实时手势 AR 应用。摄像头画面由 MediaPipe Hand Landmarker 在本机处理，识别结果通过独立的手势状态传递给 Three.js 特效层。项目不依赖付费云端 AI，也不上传摄像头帧。

当前开发重点是先交付稳定、低延迟、可演示的 Web V1。画面质量以清晰的动态几何法阵和可靠跟随为先，不把后处理、深度遮挡或复杂轨迹识别提前塞入 V1。

## 2. 阶段状态

状态说明：

- 已纳入：属于当前阶段的真实交付范围。
- 待验证：代码完成后仍需在真实摄像头和生产构建中验收。
- 未完成：明确属于后续阶段，当前界面不应以可用功能展示。

## 3. V1：基础可运行版本

### 已纳入当前 V1

- React、TypeScript、Vite Web 应用。
- 浏览器摄像头授权、视频预览、摄像头枚举与基础错误提示。
- 默认镜像的摄像头画面，以及与视频共用显示区域的调试和 WebGL 图层。
- 本地 MediaPipe Hand Landmarker 模型与 WASM 资源。
- 最多两只手、每只手 21 个关键点及 handedness 结果。
- 手掌中心、手掌宽度、屏幕旋转角、手部速度和双手距离等派生数据。
- 指数平滑及短暂丢失时的保持、渐隐和最终隐藏策略。
- 单手张掌、单手握拳、双手交互三类 V1 手势状态。
- 张掌时的手掌跟随小型法阵。
- 握拳时的法阵收缩、能量爆裂和触发冷却。
- 双手有效且距离合理时的中点大型法阵，以及随距离变化的缩放。
- 动态 Shader 法阵、反向旋转圆环、能量核心和基础粒子。
- 可折叠控制面板和开发调试信息。
- 三档可切换性能参数、原创 Web Audio 基础音效、音量和重复播放保护。
- 页面隐藏时暂停非必要计算，以及卸载时释放摄像头、动画循环和 WebGL 资源的基础机制。
- README 和 docs 目录中的架构、手势、特效、性能及已知问题文档。

### V1 完成前待验证

- 在当前稳定版 Chrome 和 Edge 中完成摄像头授权、拒绝、重试、切换设备测试。
- 检查 16:9、4:3 摄像头，以及宽屏、近方形、窄窗口和全屏下的坐标对齐。
- 验证张掌到法阵、张掌转握拳、双手靠近与分开的完整行为。
- 确认同一握拳不会连续爆裂，短暂丢手不会让效果瞬间闪灭。
- 已完成类型检查、lint、生产构建，以及 Chrome 假摄像头 production preview 烟测；仍需真实摄像头手测。
- 在参考电脑上记录 60 秒 FPS、推理耗时、渲染耗时和粒子峰值。
- 完成至少 15 分钟持续运行检查，确认粒子和 WebGL 资源没有持续累积。

### V1 验收边界

V1 不以“有文件或有开关”为完成标准。摄像头、识别、手势和特效必须组成可实际演示的闭环；设置面板中展示的 V1 控件必须真实生效。属于后续阶段的控件应隐藏或明确禁用并标注版本，不能用无效 UI 冒充完成。

## 4. V1.1：手势与特效增强

以下功能当前未完成：

- 捏合事件的能量点与轨迹消费；基础开始、移动、结束状态事件已实现。
- 拇指与食指之间的小型能量点。
- 空中轨迹绘制、轨迹衰减和简单符号绘制。
- 更严格的“先靠近再快速展开”时间窗口；V1 已实现基础距离速度释放事件。
- 大型冲击波、光线和拖尾效果。
- 补齐持续能量、完整冲击波和轨迹绘制音效；基础出现、爆裂、蓄力/释放合成音已完成。
- 分效果独立音量、更多音色与更细的用户交互解锁兼容处理；全局静音、音量与重复播放保护已完成。
- 基于真实硬件数据继续校准 Low、Balanced、High 三档；三档参数切换已完成。
- 更完整的粒子对象池和 GPU 粒子优化。
- 更多 Shader 噪声、流光和波纹效果。
- Web Worker 推理迁移与更严格的渲染线程隔离。
- 基础圆形轨迹识别；完整双手画圆激活规则根据实测再决定是否延后。

以下功能当前未完成：

## 7. 当前技术债

- MediaPipe Web 的 detectForVideo 是同步调用。若推理仍在主线程，复杂场景可能造成短帧；V1.1 应优先验证 Worker 方案。
- Hand Landmarker 不返回逐关键点置信度。当前只能使用 handedness 分数、模型门槛和规则派生的手势置信度。
- 左右手在遮挡、交叉或极端角度下可能短暂换序，需要继续增强手部身份连续性。
- 张掌、握拳和双手相对均为几何启发式，需要更多光照、肤色、背景和摄像头样本调参。
- “普通电脑”不是可复现的性能基线，必须在 PERFORMANCE.md 中记录实测硬件、浏览器、分辨率和推理频率。
- WebGL context lost 的完整恢复流程、真实手势自动化样本和长时间内存基准仍需补强；假摄像头启动烟测已提供。

## 8. 文档更新规则

每个阶段完成时必须同步：

1. 将本文件中的功能从“未完成”移动到当前阶段的已纳入列表。
2. 在 PERFORMANCE.md 记录真实测试环境和结果。
3. 在 KNOWN_ISSUES.md 删除已解决问题，并增加新发现的问题。
4. 仅在真实浏览器和生产构建通过后，才在 README 中宣布阶段完成。
