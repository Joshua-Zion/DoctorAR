# DoctorAR 开发计划

## 1. 项目定位

DoctorAR 是一个在浏览器中运行的本地实时手势 AR 应用。摄像头画面由 MediaPipe Hand Landmarker 在本机处理，识别结果通过独立的手势状态传递给 Three.js 特效层。项目不依赖付费云端 AI，也不上传摄像头帧。

当前已经完成 Web V1 与 V1.1 的代码闭环。画面质量以清晰的动态几何法阵、可靠跟随、自由捏合轨迹和严格快速展开反馈为先；后处理、深度遮挡与复杂轨迹识别不提前塞入当前阶段。

## 2. 阶段状态

状态说明：

- 已纳入：属于当前阶段的真实交付范围。
- 待验证：代码完成后仍需在真实摄像头和生产构建中验收。
- 未完成：明确属于后续阶段，当前界面不应以可用功能展示。

## 3. V1：基础可运行版本

### 已纳入当前 V1

- React、TypeScript、Vite Web 应用。
- 浏览器摄像头授权、视频预览、摄像头枚举与基础错误提示。
- 默认镜像的摄像头画面，以及与视频共用显示区域的调试和 WebGL 图层。
- 本地 MediaPipe Hand Landmarker 模型与 WASM 资源。
- 最多两只手、每只手 21 个关键点及 handedness 结果。
- 手掌中心、手掌宽度、屏幕旋转角、手部速度和双手距离等派生数据。
- 指数平滑及短暂丢失时的保持、渐隐和最终隐藏策略。
- 单手张掌、单手握拳、双手交互三类 V1 手势状态。
- 张掌时的手掌跟随小型法阵。
- 握拳时的法阵收缩、能量爆裂和触发冷却。
- 双手有效且距离合理时的中点大型法阵，以及随距离变化的缩放。
- 动态 Shader 法阵、反向旋转圆环、能量核心和基础粒子。
- 可折叠控制面板和开发调试信息。
- 三档可切换性能参数、原创 Web Audio 基础音效、音量和重复播放保护。
- 页面隐藏时暂停非必要计算，以及卸载时释放摄像头、动画循环和 WebGL 资源的基础机制。
- README 和 docs 目录中的架构、手势、特效、性能及已知问题文档。

### 当前仍待真实环境验证

- 在当前稳定版 Chrome 和 Edge 中完成摄像头授权、拒绝、重试、切换设备测试。
- 检查 16:9、4:3 摄像头，以及宽屏、近方形、窄窗口和全屏下的坐标对齐。
- 验证张掌到法阵、张掌转握拳、双手靠近与分开的完整行为。
- 确认同一握拳不会连续爆裂，短暂丢手不会让效果瞬间闪灭。
- 已完成类型检查、lint、生产构建、Vitest 36 项测试，以及假摄像头浏览器烟测；仍需真实摄像头手测。
- 在参考电脑上记录 60 秒 FPS、推理耗时、渲染耗时和粒子峰值。
- 完成至少 15 分钟持续运行检查，确认粒子和 WebGL 资源没有持续累积。

### V1 验收边界

V1 不以“有文件或有开关”为完成标准。摄像头、识别、手势和特效必须组成可实际演示的闭环；设置面板中展示的 V1 控件必须真实生效。属于后续阶段的控件应隐藏或明确禁用并标注版本，不能用无效 UI 冒充完成。

## 4. V1.1：手势与特效增强

### 已完成

- `PINCH_START / PINCH_MOVE / PINCH_END` 已接入视觉与音频消费；能量点固定在拇指尖与食指尖中点。
- 空中轨迹支持自由绘制、简单符号表现和按寿命自动衰减。当前不包含圆形闭合识别或字符分类。
- 双手释放采用严格顺序：候选阶段保留靠近历史，Active 后再于 360 ms 释放窗口内快速展开；慢展开、姿态失效或进入画面时已经分开的姿态不会触发。
- `TWO_HAND_RELEASE` 使用固定容量冲击波池；每次冲击波按触发中点到视口最远角计算终止半径，覆盖完整画面。
- 新增轨迹与冲击波 Shader，包含流光、噪声、扩散圆环、回波、光束和中心闪光。
- 持续法阵能量、捏合轨迹与冲击波使用原创 Web Audio 合成；音效默认关闭，真实点击解锁后播放确认音，并显示 ready / suspended / blocked 状态。
- 粒子、轨迹段和冲击波均采用固定容量；Low / Balanced / High 三档分别限制推理、DPR、粒子、轨迹和冲击波规模。
- MediaPipe Hand Landmarker 已迁入 ImageBitmap Worker 默认路径；只允许单个请求在途，繁忙时丢帧并计数，Worker 不可用时回退主线程。
- 调试面板已显示 WORKER / MAIN、Worker 往返耗时、推理 FPS、丢弃帧数、活动轨迹段与冲击波数量。

### 已完成的自动验证

- Vitest 36 项通过：18 / 28 / 40 FPS 释放、噪声与漏帧、候选/激活和重识别保护、捏合/握拳仲裁、MOVE-only 轨迹恢复、粒子密度、音频解锁，以及 Worker reset 后旧结果隔离。
- 2026-08-01 无头 Edge 假摄像头生产预览烟测确认：`WORKER` 后端生效，音频真实用户激活后为 `ready`，密集爆裂、MOVE-only 轨迹与冲击波为实际 WebGL 绘制，没有页面异常、控制台错误或网络请求失败。

### 尚待验收

- 在真实摄像头上校准不同手型、距离、光照和遮挡下的捏合与快速展开阈值。
- 完成 Chrome / Edge 真实摄像头验证，并补充其他桌面浏览器兼容性结果。
- 记录 60 秒性能基准与至少 15 分钟持续运行结果，确认固定池、Worker 和音频节点长期稳定。

## 7. 当前技术债

- MediaPipe Web 的 `detectForVideo` 仍是同步调用，但默认在 Worker 内执行。初始化或首次运行失败会受控回退到最高 18 FPS、低档输入尺寸的主线程路径；该路径仍可能造成短帧，需要继续记录后端状态和往返耗时。
- Hand Landmarker 不返回逐关键点置信度。当前只能使用 handedness 分数、模型门槛和规则派生的手势置信度。
- 左右手在遮挡、交叉或极端角度下可能短暂换序，需要继续增强手部身份连续性。
- 张掌、握拳和双手相对均为几何启发式，需要更多光照、肤色、背景和摄像头样本调参。
- “普通电脑”不是可复现的性能基线，必须在 PERFORMANCE.md 中记录实测硬件、浏览器、分辨率和推理频率。
- WebGL context lost 的完整恢复流程、真实摄像头手势样本、跨浏览器结果和长时间内存基准仍需补强；假摄像头开发烟测已提供。

## 8. 文档更新规则

每个阶段完成时必须同步：

1. 将本文件中的功能从“未完成”移动到当前阶段的已纳入列表。
2. 在 PERFORMANCE.md 记录真实测试环境和结果。
3. 在 KNOWN_ISSUES.md 删除已解决问题，并增加新发现的问题。
4. 仅在真实浏览器和生产构建通过后，才在 README 中宣布阶段完成。
