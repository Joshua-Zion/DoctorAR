# DoctorAR

DoctorAR 是一个基于浏览器摄像头的实时手势 AR 项目。它使用 MediaPipe Hand Landmarker 在本机识别双手，再由 Three.js、WebGL、动态 Shader 和粒子系统绘制原创几何法阵。

当前版本已经完成可运行、可演示的 Web V1 与 V1.1：在基础摄像头、手部跟踪和法阵闭环上，加入捏合轨迹、严格双手快速展开、全屏冲击波、原创持续音色和 Worker 推理。人物遮挡与电影级后处理仍属于 V2。

## 当前 V1 / V1.1 能力

- 浏览器摄像头授权、预览、设备选择、目标分辨率与实际分辨率显示。
- 最多同时识别两只手，每只手读取 21 个关键点、世界坐标和左右手分类。
- 计算手掌中心、掌宽、屏幕旋转、手指伸展、手部速度和双手距离。
- 指数平滑、短暂丢失保持、渐隐和最终隐藏，减少法阵闪烁。
- 单手张掌、单手握拳和双手法阵三类状态。
- 单手法阵平滑跟随掌心，并随掌宽和掌部角度变化。
- 握拳时让当前法阵收缩，并触发一次受冷却保护的密集粒子爆裂；默认约 180 粒，且按性能档限制单次峰值。
- 双手有效且距离合理时，在两掌中点生成大型法阵；需要四根长指明确伸展并稳定保持约 130 ms。双掌相对可进入，双掌朝前时还要求两手距离较近且高低基本一致。
- 原创动态 Shader、反向旋转圆环、能量核心、呼吸亮度和基础火花粒子。
- 捏合时在拇指与食指中点显示能量点，并按移动路径绘制会自动衰减的空中发光轨迹；可自由绘制简单符号。
- 双手必须先靠近完成蓄力，再在 360 ms 释放窗口内快速展开，才触发覆盖到视口最远角的大型冲击波。
- `pinchTrail` 与 `shockwave` Shader 提供轨迹流光、能量点、扩散圆环、回波、光束和中心闪光。
- 粒子、轨迹和冲击波均使用固定容量，Low / Balanced / High 三档分别限制推理、DPR 和各类特效上限。
- 可折叠控制面板、关键点/骨架调试层和性能信息。
- 默认关闭的原创 Web Audio 合成音效，包括持续能量、捏合轨迹和冲击波音色；开关会执行真实浏览器解锁、播放确认音并显示音频状态。
- 五种统一配置的视觉主题：琥珀、蓝色空间、紫色混沌、绿色自然和红色火焰。
- MediaPipe 模型和 WASM 随项目本地加载；摄像头帧不发送到服务器。
- 优先通过 MediaPipe ImageBitmap Worker 推理，保持单个 in-flight 帧；Worker 不可用时自动回退主线程，并在调试面板显示后端、往返耗时、推理 FPS 和丢帧数。

V1.1 的轨迹是自由绘制与简单符号反馈，不包含圆形闭合识别或手写内容分类。人物遮挡、手掌透视、Bloom、色差、折射和空间扭曲仍属于 V2。

## 三类 V1 手势

### 1. 单手张掌

让完整手掌进入画面，掌面大致朝向摄像头并张开手指。稳定保持片刻后，掌心会出现小型法阵。

使用建议：

- 保持手腕和五指尽量完整可见。
- 不要离镜头过近，以免手指或掌缘出画。
- 法阵尺寸会随识别到的掌宽变化。

### 2. 单手握拳

先张掌激活法阵，再自然握拳。当前法阵会快速收缩并产生一次粒子爆裂。

握拳事件有保持时间和冷却时间；持续握拳不会每帧重复爆裂。

### 3. 双手法阵

让两只手同时进入画面，双掌大致相对并保持在合理距离。大型法阵会出现在两掌中点。

- 两手分开时法阵增大。
- 两手靠近时法阵缩小。
- 任一手短暂丢失时，效果会保持并渐隐，而不是立即闪灭。

快速展开不是“看到两手分开就触发”：先让两只手的四根长指明确张开并保持约 130 ms；推荐双掌相对。若双掌同时朝向镜头，两手需保持在相近高度且不要分得过宽。中央大法阵出现后，再把两掌靠近到约四分之一画面宽度，随后在 360 ms 内向两侧快速展开。成功后会从双手中点发射固定池冲击波，半径按触发点到视口最远角计算。短暂漏掉一帧可以继续，但 80 ms 的旧手部数据不会触发释放。

### V1.1 捏合与空中绘制

拇指与食指指腹捏合，稳定约 60 ms 后，能量点会出现在两指尖中点；保持捏合并移动手即可形成发光轨迹。松开后能量点和轨迹按寿命自动衰减，左右手可独立绘制。轨迹移动事件能在漏掉起始事件时自行恢复，捏合也不会再被握拳冷却时间阻塞。

当前只支持自由轨迹和简单符号的视觉表达，不会判断轨迹是否闭合成圆，也不会识别具体字符。

## 五层画面架构

| 层级 | 职责 |
| --- | --- |
| 摄像头视频层 | 显示默认水平镜像的实时画面 |
| 手势调试层 | 绘制 21 个关键点、骨架和识别标记，默认关闭 |
| Three.js 特效层 | 以透明 WebGL Canvas 绘制法阵、Shader 和粒子 |
| UI 控制层 | 处理启动、错误提示、设备和特效设置 |
| 性能信息层 | 显示 FPS、推理耗时、渲染耗时和粒子数量 |

五层共享同一显示容器和坐标映射。映射逻辑需要同时处理视频镜像、宽高比、裁剪偏移、浏览器缩放、DPR 和全屏变化。

数据流为：

Camera → Hand Landmarker → 手部特征与平滑 → 手势状态机 → 手势事件/连续姿态 → Three.js 特效。

特效模块只消费手势数据，不直接依赖 MediaPipe。

## 本地模型与隐私

运行时资源位于：

- public/models/hand_landmarker.task
- public/mediapipe/wasm/

模型和 WASM 由当前站点静态加载，推理在浏览器本地执行。应用只请求视频摄像头，不请求麦克风，也没有上传摄像头帧的后端接口。

摄像头权限仍由浏览器和操作系统控制。停止页面或卸载应用时，程序会停止 MediaStream tracks 并释放相关资源。

## 环境要求

- Windows、macOS 或 Linux 桌面系统。
- 当前稳定版 Chrome 或 Edge。
- 可用摄像头和 WebGL。
- Node.js 20.19+，或 Node.js 22.12+。
- npm，随 Node.js 一同安装。

建议使用当前 Node.js LTS。Firefox、Safari 和移动浏览器尚未列入 V1 的正式验证范围。

## 安装

在 PowerShell 中进入项目目录：

~~~powershell
cd D:\Projects\DoctorAR
npm install
~~~

若需要严格按 package-lock.json 重新安装，可使用：

~~~powershell
npm ci
~~~

## 开发与检查

启动开发服务器：

~~~powershell
npm run dev
~~~

浏览器打开终端显示的 localhost 地址。按页面提示启动摄像头，并在浏览器权限提示中选择“允许”。

单独执行 TypeScript 检查：

~~~powershell
npm run typecheck
~~~

执行 41 项 Vitest 手势、视觉、音频与 Worker 生命周期测试：

~~~powershell
npm test
~~~

执行 lint：

~~~powershell
npm run lint
~~~

生成生产构建：

~~~powershell
npm run build
~~~

在本地验证生产产物：

~~~powershell
npm run preview
~~~

保持开发服务器或 production preview 运行后，可在 Windows 的系统 Chrome/Edge 上执行假摄像头烟测：

~~~powershell
npm run smoke:browser
~~~

开发烟测用于快速验证 Worker 与 V1.1 实绘；production preview 仍用于确认模型、WASM 和 Shader 的构建路径正确。

## 摄像头权限与 HTTPS

getUserMedia 只能在安全上下文中使用：

- 本地开发的 http://localhost 可用。
- 正式部署应使用 HTTPS。
- 普通的局域网 HTTP 地址，例如 http://192.168.x.x，通常不能访问摄像头。

首次授权前，浏览器可能不会提供完整摄像头名称。授权成功后，DoctorAR 会重新枚举可用视频设备。

目标分辨率是传给浏览器的偏好，不是硬保证。控制面板会显示摄像头最终采用的实际分辨率。

如果用户在浏览器中永久拒绝权限，页面无法绕过浏览器设置重新授权，需要在地址栏的站点权限中恢复摄像头访问。

## 浏览器支持

V1 优先支持并验证 Windows 上当前稳定版：

- Google Chrome
- Microsoft Edge

其他桌面浏览器可能能够运行，但尚未完成正式兼容性验证。移动端、Tauri、Electron、Android、HarmonyOS 和 iOS 封装均不属于当前 V1。

## 控制面板

当前控制项包括：

- 开启或关闭手势识别。
- 开启或关闭关键点和手部骨架。
- 手势灵敏度、坐标平滑和触发冷却。
- 开启或关闭法阵和粒子。
- 五种能量主题。
- 法阵尺寸、亮度、粒子密度和粒子速度。
- 摄像头选择、目标分辨率和实际分辨率。
- 调试模式和全屏。
- 低性能、平衡、高质量三个参数预设入口。
- 原创合成音效开关与音量。

性能预设会实际调整推理频率、DPR 上限和粒子上限；目标分辨率仍可独立选择。不同硬件上的完整标定与基准仍需继续验证，预设名称不代表已经在所有设备达到某个 FPS。

## 调试信息

调试模式默认关闭。开启后可以查看：

- 手部关键点和骨架。
- 左右手、当前手势和派生分数。
- 掌心、掌宽、速度和近似掌面朝向。
- 双手距离及距离变化速度。
- FPS、推理耗时、渲染耗时、Draw Calls、活动粒子、轨迹段和冲击波数量。
- 当前视觉推理后端（WORKER / MAIN）、Worker 往返耗时、推理 FPS 和丢弃的推理帧数。

MediaPipe Web Hand Landmarker 不返回真实的逐关键点置信度。界面中的分类置信度来自 handedness，手势/追踪质量是 DoctorAR 规则派生值，不能解释成每个点的模型置信度。

## 性能说明

DoctorAR 的目标是普通电脑保持 30 FPS 以上，并尽量将手势到视觉反馈控制在 100 ms 内，但当前 README 不把这些目标写成已经在所有设备实测达成。

MediaPipe Web 的 `detectForVideo` 是同步调用。V1.1 默认把按预设缩放后的摄像头帧转为可转移 `ImageBitmap`，交给 Worker 内的 Hand Landmarker；同一时刻只允许一个请求在途，繁忙时丢弃新帧而不堆积队列。Worker 初始化或首次运行失败时会受控回退到主线程；回退路径固定限制为最高 18 FPS 和低档输入尺寸，因此仍可能短暂阻塞主线程，但不会持续创建失败帧或堆积 Worker 队列。

Low / Balanced / High 三档分别限制粒子、轨迹段和冲击波固定池，并调整推理频率、输入长边和 DPR。测试方法和结果记录规则见 [性能与验证](docs/PERFORMANCE.md)。

- 真实摄像头手势、60 秒性能基准、15 分钟持续运行和跨浏览器兼容性仍待验证；上述烟测不能替代这些验收。

## 常见故障

### 没有弹出摄像头授权

- 确认页面来自 HTTPS 或 localhost。
- 检查浏览器地址栏中的站点摄像头权限。
- 若曾经拒绝，请恢复权限后刷新或点击重试。

### 提示没有摄像头或摄像头被占用

- 确认设备已连接并被系统识别。
- 关闭会议、录屏或其他正在占用摄像头的应用。
- 在控制面板切换到系统默认摄像头后重试。

### 摄像头名称为空

浏览器通常会在授权前隐藏设备标签。先允许摄像头访问，再重新打开设备列表。

### 选择的分辨率没有生效

浏览器和硬件可以回退到最接近的可用模式。请以控制面板显示的“实际分辨率”为准。

### 模型或 WASM 加载失败

- 不要直接双击 index.html。
- 使用 npm run dev 或 npm run preview。
- 检查 public/models 和 public/mediapipe/wasm 是否完整。
- 部署到子路径时检查静态资源基路径和浏览器 Network 面板。

### 能看到手，但没有法阵

- 确认手势识别和魔法阵开关已开启。
- 提高手部光照，让完整手掌进入画面。
- 张掌时让掌面大致朝向镜头，并稳定保持片刻。
- 尝试调整手势灵敏度。

### 法阵或关键点与画面错位

- 确认页面没有被第三方样式或浏览器扩展改变视频布局。
- 切换窗口大小或全屏后等待布局重算。
- 记录摄像头宽高比、窗口尺寸和浏览器版本，并提交复现信息。

### 帧率较低

- 选择低性能预设或 480p。
- 关闭调试、关键点和骨架。
- 降低粒子密度，或暂时关闭粒子。
- 关闭占用 GPU 的其他页面和应用。

### 全屏没有响应

全屏 API 必须由真实点击等用户操作触发。请使用控制面板中的全屏按钮，并检查浏览器是否拦截该请求。

### 没有声音

- 音效默认关闭，请在控制面板主动开启；状态显示“音频已解锁”并听到 660→880 Hz 确认音后，手势音效才会播放。
- 若状态显示“浏览器阻止播放”或“音频已暂停”，再点击页面或按任意键恢复，并确认系统输出设备与网页标签页没有静音。
- 默认音量为 30%，爆裂和冲击波含普通笔记本扬声器更容易播放的中频瞬态。
- V1 使用原创 Web Audio 合成音色，不会播放电影或外部素材音频。

## 已知限制

- Worker 为默认推理路径；初始化或首次运行失败后的主线程回退虽限制为 18 FPS 和低档输入尺寸，仍可能造成短帧。
- 低光、快速运动、侧掌、手背、手指出画和双手互相遮挡会降低识别稳定性。
- 双手交叉时 handedness 和手部顺序可能短暂变化。
- 掌面朝向是 landmarks 几何近似，不是完整六自由度手部姿态。
- V1 没有人物分割、真实深度遮挡和后处理。
- 空中轨迹目前只支持自由绘制与简单符号，不支持圆形闭合识别或字符分类。
- 性能目标需要在具体硬件、摄像头分辨率和浏览器版本下分别测量。
- WebGL context lost 的完整自动恢复、真实摄像头长时间测试和跨浏览器测试仍需补强。

完整列表见 [已知问题](docs/KNOWN_ISSUES.md)。

## 原创与版权

- 法阵主体使用原创程序化几何、Shader 和粒子，不复制任何电影中的具体法阵图案。
- 项目不使用角色 Logo、电影截图、电影原声或未经授权的素材包。
- 后续新增纹理、模型或音效时，必须记录来源、许可证和对应文件。
- MediaPipe、Three.js、React 等第三方软件仍遵循各自许可证。

DoctorAR 可以使用“奇幻魔法、几何法阵、橙金能量、粒子火花”等通用视觉语言，但不宣称与任何影视作品或角色存在授权、合作或关联。
